# Frame queue benchmark

This benchmark compares two frame-delivery policies under a controlled drain
delay:

- `anchor`: the current Anchor policy. It admits frames to a bounded FIFO
  queue, then the drain keeps the newest queued frame before each send.
- `latest`: a comparison policy with one pending slot. A new frame replaces
  any unsent frame.

`latest` is an experiment only. It is not used by Anchor.

## Run

From the repository root:

```bash
cargo run --release --manifest-path anchor-desktop/tools/frame-queue-bench/Cargo.toml -- \
  --frames 600 --fps 60 --queue-depth 2 --drain-ms 0
```

The normal local sender baseline uses `--drain-ms 0`. To expose policy under a
controlled sustained bottleneck, use a delay greater than the source frame
period, for example:

```bash
cargo run --release --manifest-path anchor-desktop/tools/frame-queue-bench/Cargo.toml -- \
  --frames 300 --fps 60 --queue-depth 2 --drain-ms 100 --policy both
```

The benchmark creates in-memory frame buffers. It does not encode video or
send data over the network.

## Options

| Option | Default | Meaning |
| --- | ---: | --- |
| `--frames N` | `600` | Number of frames to produce. |
| `--fps N` | `60` | Frame production rate. |
| `--queue-depth N` | `2` | Anchor subscriber queue capacity. |
| `--frame-bytes N` | `27648` | Size of each simulated encoded frame. |
| `--drain-ms N` | `0` | Delay after dequeuing each frame. |
| `--policy P` | `both` | `anchor`, `latest`, or `both`. |

Use `--help` to print the command syntax. Numeric options must be positive,
except `--drain-ms`, which may be zero.

## Read the results

- `produced`: frames generated by the producer.
- `rejected at admission`: frames the bounded Anchor queue could not accept.
- `replaced/coalesced before send`: frames discarded in favor of a newer frame.
- `delivered`: frames that reached the simulated sender.
- `output frame-ID gaps`: produced frames skipped by the output.
- `production to dequeue`: age when the drain picked up a frame.
- `production to simulated send completion`: age after the configured drain
  delay. This is the main latency measure when the drain is slow.
- `effective send rate`: delivered frames divided by the run time.

Each latency line reports mean, minimum, p50, p95, p99, and maximum.

## Interpreting a run

Start with `--drain-ms 0` for a local baseline. Then increase the delay to
create a sustained bottleneck. A delay longer than the source frame period
should produce skipped frame IDs and expose the freshness/latency trade-off
between the policies.

`--drain-ms` is an intentional test stall. It does not measure normal
`send_to` performance and does not reproduce real network conditions.
